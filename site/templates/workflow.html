Before the first run

Make readiness legible.

  1. 01

    Locate the binary.

    Show the configured path, discovery result and executable readiness. A bare checksum match means it matches the recorded checksum; it is different from a signed launcher’s signature verification.

  2. 02

    Bind the project and daemon.

    Explain project scope, transport and autostart state. A disconnected daemon is a connectivity condition, not a failed verification verdict.

  3. 03

    Configure the chosen model.

    Keep local or hosted provider details in settings. Secrets remain masked, and diagnostic copies redact credentials.

  4. 04

    Inspect optional adapters.

    Optional intelligence and verification providers enrich neutral interfaces. The native baseline does not acquire a sibling-product dependency.
