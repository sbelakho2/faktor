A goal, a candidate and a visible evidence basis. Each part does a different job.

01 / INTENT

Compile the task.

Keep the goal, criteria, invariants, risks and proof obligations together before work starts.

02 / PLAN

03 / CANDIDATE

Separate the edit.

Transactions, checkpoints and isolated candidates bound changes before integration.

The completion chain

A green result has a scope.

Required-check acceptance, claim evidence, integration and requested finish actions stay distinct. A result for an earlier candidate cannot certify a different landed state.

  1. 1.

    Required acceptance. Every required result must be present and pass. Missing evidence stays Pending; a failure stays Fail.

  2. 2.

    Claim evidence. Name the claim and the candidate snapshot. Unavailable means no verdict; refusal is a separate outcome.

  3. 3.

    Integration. Keep verified and landed identities visible. Recheck a state that differs from the verified candidate.

  4. 4.

    Finish actions. Local changes, commit, push and native pull request are user choices with durable outcomes.

The outcome ledger counts a verified change when it is accepted and integrated with a deterministic-checks final basis. A passing empty check set does not establish that condition.
