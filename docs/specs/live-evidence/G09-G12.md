## Defects fixed (with regression tests)

### 1. Configured billing plan could never be active (F275/F273/F281)

Symptom: a locally configured `[billing]` plan resolved (`plan_found:true`) but
every admission/value entitlement refused `subscription_inactive`; there was
no local surface to write the subscription row.

Fix: additive `[billing.subscription]` (`plan_id`, optional `status`,
`expires_ms`) validated against the plan table; startup writes the durable
`Subscription` row for the configured billing organization (idempotent put,
no invoice/vendor event). Files:

- `crates/cli/src/config/billing.rs`
- `crates/cli/src/daemon/serve.rs` (`provision_billing_subscription`)

Regression tests:

- `crates/cli/src/config/billing.rs::tests` (5 tests: optional/defaults,
  unknown plan, bad status, negative expiry, hostile shapes)
- `crates/cli/src/daemon/serve.rs::billing_subscription_tests::configured_subscription_is_provisioned_and_read_back`

Live proof: after restart with the section, `/native/entitlements` returned
`subscription_active:true` and `/native/value-entitlements` granted the 10
mapped entitlements; the private-runner placement then succeeded.

### 2. Remote placement failed on every prompt/task receipt (F281/F230)

Symptom: `POST /native/session/{id}/task-runs` returned HTTP 500
`ordinary prompt did not yield an in-session op id` when the worker plane
placed the run remotely; the job was created but the adapter rejected the
receipt. `PromptReceipt.op_id` was non-optional.

Fix: `op_id` is optional with an explicit `TaskRunMode`; remote receipts
serialize `op_id:null`; recovery accepts a remote fact and still refuses a
missing op id on an in-session fact. Files:

- `crates/server/src/native/prompt.rs`
- `crates/server/src/native/task.rs`
- `crates/server/src/native/session.rs`
- `crates/server/src/native/admission_recovery.rs`

Regression tests:

- `crates/server/src/native/admission_recovery.rs::receipt_tests` (2 tests:
  remote receipt `op_id:null`; in-session missing op id still loud)

Live proof: task-run returned `{"run_id":"job_6b48…","state":"Remote"}`;
claim/result completed the job.

### 3. Unavailable root verification parked the task at `Verifying` forever (F244/F252)

Symptom: when root verification could not produce a verdict (no derived
checks / missing reviewer opinion), the settlement persisted a **pending**
fact and returned without a terminal edge; the task row stayed `verifying`
until an operator cancelled it.

Fix: persist `unavailable` (a settled fact) and move a `Verifying` row back
through the legal `Reverify` edge to `NeedsVerification`; both the in-session
and orchestrated unavailable branches do this. Files:

- `crates/orchestrator/src/task_executor/settlement.rs`

Regression test:

- `crates/orchestrator/src/task_executor_tests/tests_control.rs::no_op_run_without_a_reviewer_verdict_refuses_completion`
  now asserts `TaskState::NeedsVerification` (test passes).

Live proof: the same no-op/unavailable path now leaves `task.state=needs_verification`
(proof route reports `proofState:"unverified"`), not a parked
`verifying` row.

### Fixes and regression tests

- **F219 console capture** — `crates/browser/src/console.rs` adds a bounded
  per-page console/log/exception ring (512 records, 8 KiB text, 2 KiB
  source, URL redaction). `Page::console()` refuses typed once the
  observation stream is incomplete; the foundation surface syncs rows as
  `kind=console`. Tests:
  `console::tests::*`, browser
  `console_observations_are_captured_bounded_and_ordered`.
- **F222 download runtime** — response-stage Fetch is always observed; a
  default-denied attachment is recorded (`Rejected`, sanitized filename),
  denied at the response stage, and transitions the navigation to a typed
  `download_blocked` failure instead of waiting for a load event that never
  fires. Tests:
  `download::tests::fetch_patterns_always_observe_the_response_stage`,
  browser `attachment_navigation_is_default_denied_typed_without_deadline_hang`.
- **F225/F226/F235 LSP** — `crates/lsp/src/diagnostics.rs` adds a bounded,
  versioned `publishDiagnostics` hub (256 documents, 2048 diagnostics each),
  progress-aware settled waits, normalized/bounded code actions, and
  exact-range proposal-only application. Native routes:
  `GET /native/lsp/diagnostics`, `POST /native/lsp/code-actions` (typed
  `lsp_disabled`/`lsp_unavailable`/`lsp_diagnostics_timeout`, path traversal
  and symlink escapes refused). The daemon shares ONE `LspManager` with the
  semantic fallback. VS Code publishes daemon diagnostics to Problems and
  registers a Quick Fix provider (`faktor.refreshLspDiagnostics8`), applying
  only the operator-selected edit. Tests: `diagnostics::tests::*`, live
  `live_rust_analyzer_diagnostics_and_code_actions`, server
  `lsp_routes_are_typed_when_no_language_server_manager_is_wired`.
- **F230 ACP prompt routing/output** — sync-backend final transcript is now
  projected as official `agent_message_chunk`/`agent_thought_chunk` frames
  (`crates/acp/src/sync_bridge.rs`), so a prompt returns the assistant text
  instead of only `end_turn`. Routing itself was the live-config quality
  declaration, not a router refusal. Test:
  `sync_backend_final_transcript_is_projected_as_official_chunks`.
- **F232 ACP framing desync** — header-level framing violations (invalid or
  duplicate `Content-Length`, malformed header, missing length) are fatal:
  typed parse error, then clean close. Body-level errors with a known
  boundary remain recoverable. Test:
  `malformed_header_is_rejected_typed_and_never_desyncs_into_the_next_frame`.
- **G10 verified chain** —
  - Edit engine now authorizes the EXACT scoped shadow root the daemon
    opened (no more `workspace 1 is not registered`), with a bounded
    authorized-root set; tests
    `authorized_scoped_candidate_root_is_editable_but_unauthorized_is_not`.
  - Verification env preserves the daemon's approved Rust toolchain homes
    across the scratch HOME rewrite (rustup no longer says "no default");
    test `scratch_home_preserves_approved_toolchain_homes`.
  - Inline `#[cfg(test)]` selectors are discovered from the changed source

    shared parser with the contract compiler; tests
    `inline_tests_in_a_plain_source_file_derive_executable_test_checks`,
    `legacy_client_criteria_fact_converges_to_the_derived_typed_row`.
  - Root verification fact is byte-bounded with explicit `truncated`/counts
    (settlement no longer fails on a >4 KiB list); test
    `root_verification_fact_is_bounded_and_settlement_safe`.
  - Build caches (`target`, `node_modules`, `.venv`, …) are excluded from
    canonical manifests/change sets, so a derived check cannot pollute
    landing or drift identity; test
    `build_caches_are_never_manifested_or_digest_bound`.
